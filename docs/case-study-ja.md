# Onside 技術事例：手持ちの RTX 2080 Ti で計算性能の変化を検証

著者：Onside Lab

## 課題

ローカル LLM や画像生成を手持ちの GPU で速くしたい。機器の追加購入を検討する前に、現在の RTX 2080 Ti（TU102）で計算性能が変わる余地を実機で確かめました。Onside の技術事例として、実施した条件と観測できた範囲を記録しています。

## 方針

解除の実装には [nv-uefi-unlocker](https://github.com/physicsdolphin/nv-uefi-unlocker) を使用しました。v2.1.6、commit `9932cfbe1c2f6ebc0759139a2b0949703c00f82f` に固定し、診断、GSP モードへの変更と再起動、解除の1回起動、Windows 復帰後の測定へ段階的に進めました。解除の仕組み自体は上流の成果であり、ここでの取り組みは条件を固定した実機検証です。

各段階で、進めるための確認と戻し方を用意しました。診断で条件が合わなければ先へ進まない。GSP の動作を確認できなければ元の設定へ戻す。解除の途中で異常があれば同じセッションで繰り返さず、完全な電源断後に通常起動へ戻す。Windows に復帰した後も、速度だけでなく数値検算を確認する方針としました。

## 結果

1台での1回の解除について、行列サイズ2048、5標本×20回の積を測定しました。PyTorch は2.5.1+cu121、前後の電力上限は192.5 Wです。

| 項目 | 解除前 | 解除後 |
| --- | ---: | ---: |
| FP16 入力 GEMM 中央値（TFLOPS） | 46.88 | 87.17 |
| FP32 SIMT 中央値（TFLOPS） | 12.61 | 12.27 |
| 64×64 CPU float64 参照の数値検算 | 合格 | 合格 |

FP16 入力 GEMM には約1.86倍の変化が見られました。FP32 には同様の増加は見られませんでした。SM クロックの代表値は1590→1575 MHzでしたが、測定中に変動しており固定クロックでの比較ではありません。元の中央値と測定条件は [benchmark.json](../results/benchmark.json)、工程と環境は [README](../README.md) にあります。

## 限界

この測定は短時間の行列積です。FP16 入力であることは確認していますが、カーネルの累積型は独立に計測していません。検算は64×64の別問題であり、性能測定した大行列の全要素を確認したものではありません。

ローカル LLM の応答速度や画像生成時間を測った事例ではなく、それらが1.86倍になるとは言えません。長時間の安定性、スリープからの復帰、ゲーム、他個体、複数回の起動での再現性も未検証です。解除は揮発性で、利用する起動ごとに再実行が必要になります。元の状態へ戻す場合は、解除を通さずに電源断から通常起動し、別途変更した GSP 設定も復元する必要があります。復旧を保証するものではありません。

## 中小企業が自前の GPU を使うときの考え方

行列積の性能は、既存機材を評価する一つの材料です。業務への導入判断では、使用するモデルが GPU に収まるか、必要な品質で動くか、待ち時間が実際に減るかを、対象の処理で確かめる必要があります。この事例の TFLOPS だけでは、GPU の増設を避けられるとも、導入全体の費用を下げられるとも判断できません。

追加購入との比較には、機器の性能に加え、起動のたびの作業、異常時に元へ戻す時間、保守を続けられるかも含める必要があります。今回の結果は、手持ちの GPU の計算性能を条件付きで引き出せた一例として示し、業務環境での採用可否は実際の処理と運用条件で判断します。
